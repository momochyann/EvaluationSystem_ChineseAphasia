==================================================
  栏目组组件获取模式使用说明
==================================================

一、功能概述
------------
为 栏目组性_茉 组件添加了两种获取子组件的方式：

【拖动模式】：在Inspector检视面板中手动拖入子组件
【自动寻找模式】：使用 GetComponentsInChildren 自动查找子物体（默认）

这样可以更灵活地配置栏目组，既可以精确控制使用哪些组件，也可以自动获取所有子组件。


二、Inspector配置说明
-------------------

在Unity编辑器中选择栏目组GameObject，你会看到以下配置项：

┌─ 基础配置 ─────────────────────┐
│ 维度名称: [文本框]              │
│ 组类型: [选项组性/表分择性]     │
│ 总分显示: [TextBlock拖入框]     │
└────────────────────────────────┘

┌─ 组件获取方式 ─────────────────┐
│ 获取模式: [拖动模式/自动寻找模式]│
│                                  │
│ 手动选项组群: [列表]            │
│   └ Size: 0                      │
│                                  │
│ 手动表分择性群: [列表]          │
│   └ Size: 0                      │
└────────────────────────────────┘


三、使用方法
------------

【方法一：自动寻找模式（推荐，默认）】

1. 在Inspector中设置：
   - 获取模式 = 自动寻找模式
   
2. 确保子物体上挂载了相应的组件：
   - 如果组类型是"选项组性"，子物体需要有 选项组性_茉 组件
   - 如果组类型是"表分择性"，子物体需要有 表分择性_茉 组件

3. 运行时会自动找到所有子组件并使用

优点：
✓ 简单方便，不需要手动拖入
✓ 新增子物体时自动识别
✓ 适合子组件数量较多的情况

缺点：
✗ 会获取所有子物体中的组件，可能包含不想要的
✗ 无法控制组件的顺序（按层级顺序）


【方法二：拖动模式（精确控制）】

1. 在Inspector中设置：
   - 获取模式 = 拖动模式
   
2. 根据组类型展开相应的列表：
   - 如果组类型是"选项组性"，展开"手动选项组群"
   - 如果组类型是"表分择性"，展开"手动表分择性群"

3. 设置列表Size（要添加几个组件）

4. 将场景中的组件拖入列表中的每一项

5. 运行时只会使用你拖入的组件

优点：
✓ 精确控制使用哪些组件
✓ 可以自定义组件顺序
✓ 可以使用不在子物体中的组件
✓ 可以排除某些不想要的子组件

缺点：
✗ 需要手动配置
✗ 新增组件时需要手动添加到列表


四、运行时切换模式
-----------------

也可以通过代码在运行时切换模式：

// 获取栏目组组件
栏目组性_茉 栏目组 = GetComponent<栏目组性_茉>();

// 方法1：在两种模式间切换
栏目组.切换获取模式();

// 方法2：切换到指定模式
栏目组.切换获取模式(组件获取模式.拖动模式);
栏目组.切换获取模式(组件获取模式.自动寻找模式);

// 方法3：刷新子组件（当修改了配置后）
栏目组.刷新子组件();


五、使用场景示例
----------------

【场景1：简单结构，推荐自动寻找】

GameObject结构：
栏目组A（栏目组性_茉）
  ├─ 选项组1（选项组性_茉）
  ├─ 选项组2（选项组性_茉）
  └─ 选项组3（选项组性_茉）

配置：
- 获取模式 = 自动寻找模式
- 无需配置其他

结果：自动找到3个选项组


【场景2：复杂结构，推荐拖动模式】

GameObject结构：
栏目组A（栏目组性_茉）
  ├─ 选项组1（选项组性_茉）← 要用
  ├─ 选项组2（选项组性_茉）← 要用
  ├─ 示例组（选项组性_茉）  ← 不要用
  └─ 子容器
      └─ 选项组3（选项组性_茉）← 要用

配置：
- 获取模式 = 拖动模式
- 手动选项组群: Size = 3
  - Element 0: 选项组1（拖入）
  - Element 1: 选项组2（拖入）
  - Element 2: 选项组3（拖入）

结果：只使用指定的3个选项组，排除"示例组"


【场景3：跨层级引用】

有时候组件不在子物体中，而是在其他地方：

场景结构：
界面根目录
  ├─ 栏目组容器
  │   └─ 栏目组A（栏目组性_茉）
  └─ 组件池
      ├─ 选项组X（选项组性_茉）
      └─ 选项组Y（选项组性_茉）

配置：
- 获取模式 = 拖动模式
- 手动选项组群: Size = 2
  - Element 0: 选项组X（拖入）
  - Element 1: 选项组Y（拖入）

结果：可以使用不在子物体中的组件


六、调试提示
------------

运行时会在Console输出日志，帮助你确认配置是否正确：

[自动寻找模式] 日志示例：
"[词命名] 使用自动寻找模式，找到了 5 个选项组"

[拖动模式] 日志示例：
"[词复述] 使用拖动模式，加载了 3 个选项组"

如果数量不对，请检查：
1. 获取模式是否选择正确
2. 拖动模式下列表是否配置完整
3. 自动寻找模式下子物体是否有对应组件


七、注意事项
------------

1. 组类型与手动列表要对应：
   - 组类型=选项组性 → 使用"手动选项组群"
   - 组类型=表分择性 → 使用"手动表分择性群"

2. 拖动模式下，只使用对应的手动列表：
   - 不要把选项组拖到表分择性列表中
   - 不要把表分择性拖到选项组列表中

3. 列表中不要有空引用（None）

4. 自动寻找模式会查找所有子物体（包括子物体的子物体）

5. 切换模式后会立即重新初始化并重新计算总分


八、常见问题
------------

Q: 我想要部分自动、部分手动可以吗？
A: 不可以，只能选择一种模式。建议使用拖动模式，可以混合使用任何位置的组件。

Q: 切换模式会丢失已有的选择吗？
A: 不会，选择状态保存在子组件中，切换模式只是改变获取组件的方式。

Q: 自动寻找模式会找到孙子物体的组件吗？
A: 会的，GetComponentsInChildren会递归查找所有层级。

Q: 可以在运行时动态修改手动列表吗？
A: 可以，修改后调用 刷新子组件() 方法即可生效。

Q: 哪种模式性能更好？
A: 两种模式性能相近，只在初始化时有细微差别，对运行时性能无影响。
