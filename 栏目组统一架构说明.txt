================================
栏目组统一架构说明
================================

🎯 核心改进
-----------
通过增强栏目组性_茉，支持选项组性和表分择性两种模式，
实现了完全统一的量表评估架构！


📊 代码量对比
-----------

1. 栏目组性_茉（增强版）
   - 原版：~185 行
   - 增强版：~368 行（增加了表分择性支持）
   - 新增功能：
     * 栏目组类型枚举（选项组性/表分择性）
     * 自动识别和管理两种类型的子组件
     * 统一的接口（设置/获取/清除选择）

2. 量表评估基类_茉（精简版）
   - 原版：~554 行
   - 精简版：~213 行
   - 减少：61% ⬇️
   - 移除了选项组/表分择性的直接管理，完全通过栏目组

3. 量表谈话栏（栏目组版）
   ❌ 原版：~277 行
   ✅ 新版：~14 行（仅3个方法）
   📉 减少：95% ⬇️

4. 量表复述栏（栏目组版）
   ❌ 原版：~474 行
   ✅ 新版：~36 行（3个方法+保存总分）
   📉 减少：92% ⬇️

5. 量表命名栏（栏目组版）
   ❌ 原版：~323 行
   ✅ 新版：~60 行（3个方法+输入框处理+保存总分）
   📉 减少：81% ⬇️


🔧 使用方法
-----------

### Unity层级结构

方式1：谈话记录（纯选项组）
量表谈话栏
└── 谈话栏目组（栏目组性_茉）
    ├── 维度名称: "谈话"
    ├── 组类型: 选项组性
    ├── 总分显示: TextBlock（可选）
    └── 多个选项组性_茉

方式2：复述记录（选项组 + 表分择性）
量表复述栏
├── 词复述栏目组（栏目组性_茉）
│   ├── 维度名称: "词复述"
│   ├── 组类型: 选项组性
│   ├── 总分显示: TextBlock
│   └── 多个选项组性_茉
└── 句复述栏目组（栏目组性_茉）
    ├── 维度名称: "句复述"
    ├── 组类型: 表分择性
    ├── 总分显示: TextBlock
    └── 多个表分择性_茉

方式3：命名记录（多维度选项组）
量表命名栏
├── 列名输入: TextField
├── 词命名栏目组（栏目组性_茉）
│   ├── 维度名称: "词命名"
│   ├── 组类型: 选项组性
│   └── 多个选项组性_茉
├── 颜色识别栏目组（栏目组性_茉）
└── ...其他维度栏目组


### 代码示例

最简单的量表（如理解记录）：
```csharp
public class 量表理解栏_茉 : 量表评估基类_茉
{
    protected override string 获取记录字段名称() => "理解记录";
    
    protected override bool 检查是否全部完成()
    {
        return 栏目组性群?.TrueForAll(组 => 组?.是否全部已选择 ?? false) ?? false;
    }
    
    protected override string 获取未完成提示信息() => "请完成全部理解评估";
}
```
仅14行代码！


带总分的量表（如阅读记录）：
```csharp
public class 量表阅读栏_茉 : 量表评估基类_茉
{
    protected override string 获取记录字段名称() => "阅读记录";
    
    protected override bool 检查是否全部完成()
    {
        return 栏目组性群?.TrueForAll(组 => 组?.是否全部已选择 ?? false) ?? false;
    }
    
    protected override string 获取未完成提示信息() => "请完成全部阅读评估";
    
    protected override void 保存额外数据(object 记录)
    {
        var 阅读记录 = 记录 as 阅读记录;
        if (阅读记录 == null) return;
        
        // 保存总分（栏目组自动计算）
        var 栏目组 = 栏目组性群?.FirstOrDefault();
        if (栏目组 != null)
        {
            阅读记录.阅读总分 = 栏目组.当前总分;
        }
    }
}
```
仅25行代码！


🌟 核心优势
-----------

1. **完全统一**
   - 所有量表都使用栏目组方式
   - 无论是选项组性还是表分择性，接口完全一致
   - 基类不再需要区分组件类型

2. **极度精简**
   - 谈话栏：14行代码（原277行）
   - 复述栏：36行代码（原474行）
   - 命名栏：60行代码（原323行）
   - 平均减少 89% 的代码！

3. **灵活扩展**
   - 栏目组可以是任意类型（选项组性/表分择性）
   - 可以混合使用不同类型的栏目组
   - 总分自动计算和显示

4. **自动化管理**
   - 栏目组自动发现子组件
   - 自动订阅和取消订阅事件
   - 自动计算总分并触发变化事件

5. **易于维护**
   - 组件职责单一清晰
   - 修改一处，所有量表受益
   - 新增量表只需3-4个方法

📋 栏目组类型选择指南
-----------

使用 栏目组类型.选项组性 当：
✓ 子组件是选项组性_茉
✓ 每个选项有0/1/2/3等分数
✓ 用户通过Toggle选择

使用 栏目组类型.表分择性 当：
✓ 子组件是表分择性_茉
✓ 用户通过Dropdown选择分数
✓ 需要更灵活的分数选择


🔍 对比总结
-----------

原架构问题：
❌ 基类需要管理3种列表（选项组/栏目组/表分择性）
❌ 还原和保存逻辑复杂，需要分别处理
❌ 子类代码冗长，重复代码多
❌ 难以维护和扩展

新架构优势：
✅ 基类只管理栏目组列表
✅ 栏目组内部处理不同类型组件
✅ 子类代码极简，平均15-60行
✅ 易于维护，修改集中在栏目组性_茉
✅ 接口统一，逻辑清晰


💡 最佳实践
-----------

1. 命名规范
   - 栏目组GameObject命名：{维度名称}栏目组
   - 维度名称要与保存逻辑中的switch case一致

2. 总分显示
   - 如果需要显示总分，拖入TextBlock
   - 如果不需要，留空即可
   - 栏目组会自动更新总分显示

3. 混合类型
   - 一个量表可以有多个栏目组
   - 每个栏目组可以是不同类型
   - 例如：复述栏有选项组性和表分择性两种栏目组

4. 数据保存
   - 基类自动保存所有栏目组的选择
   - 如需保存总分，重写保存额外数据方法
   - 通过维度名称（switch）区分不同栏目组
