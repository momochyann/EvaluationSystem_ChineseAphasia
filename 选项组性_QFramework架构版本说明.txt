└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ void 设置高亮组(选项组性_茉 目标选项组)                          │

│ 返回值：当前高亮的选项组实例，如果没有则返回 null                 │
│ 使用场景：需要查询当前操作状态时                                  │

┌─────────────────────────────────────────────────────────────────┐

1. 基本使用（已自动实现，无需额外代码）
   选项组会在 OnEnable/OnDisable 时自动注册/注销
   选项被选中时会自动设置高亮

2. 手动控制示例：

   // 获取当前高亮的选项组
   var 当前组 = this.GetSystem<选项组高亮管理System>().获取当前高亮组();
   if (当前组 != null)
   {
       Debug.Log($"当前操作的选项组: {当前组.选项组名称}");
   }

   // 取消所有高亮（例如在关闭评估界面时）
   this.GetSystem<选项组高亮管理System>().取消所有高亮();

   // 查询注册数量（调试用）
   int 数量 = this.GetSystem<选项组高亮管理System>().获取注册数量();
   Debug.Log($"当前注册的选项组数量: {数量}");

QFramework System 方案的优势：

✅ 1. 更好的解耦
   - 选项组不直接引用彼此
   - 通过 System 作为中介

✅ 2. 统一的访问方式
   - 使用 GetSystem<>() 获取
   - 符合 QFramework 架构规范
   - 与项目中其他代码风格一致

✅ 3. 易于扩展
   - 可以轻松添加新功能（如历史记录、撤销等）
   - 不影响现有选项组代码

✅ 4. 更好的调试体验
   - 集中的日志输出
   - 可以在 System 中添加断点调试
   - 清晰的调用链

✅ 5. 便于单元测试
   - 可以 Mock System 进行测试
   - 不依赖 Unity 场景

  // 已移除静态列表
  // 改用 this.GetSystem<选项组高亮管理System>()

旧代码：

新代码：
  this.GetSystem<选项组高亮管理System>().注册选项组(this);

旧代码：
  foreach (var 其他选项组 in 所有选项组)
  {
      if (其他选项组 != this)

          其他选项组.取消高亮();
      }
  }

  this.GetSystem<选项组高亮管理System>().设置高亮组(this);
