一、更新内容
------------
将阅读栏的维度从5个扩展为7个，细化了"字画匹配"和"执行指令"的评分。

【原来的5个维度】
1. 视读
2. 阅读指令
3. 字画匹配（单一总分）
4. 执行指令（单一总分）
5. 填空

【更新后的7个维度】
1. 视读
2. 阅读指令
3. 字画匹配-朗读
4. 字画匹配-配画
5. 执行指令-朗读
6. 执行指令-配画
7. 填空

三、Unity场景配置
-----------------

在Unity编辑器中，需要确保阅读栏的栏目组配置正确：

【栏目组性_茉 组件的维度名称设置】

需要配置7个栏目组GameObject，每个的"维度名称"字段应设置为：

1. "视读"
2. "阅读指令"
3. "字画匹配-朗读" 或 "字画匹配朗读"
4. "字画匹配-配画" 或 "字画匹配配画"
5. "执行指令-朗读" 或 "执行指令朗读"
6. "执行指令-配画" 或 "执行指令配画"
7. "填空"

注意：代码支持两种命名格式（带横杠或不带），建议统一使用带横杠的格式。


四、数据兼容性
--------------

【旧数据处理】
如果之前已经保存了阅读记录数据，旧数据中只有：
- 字画匹配总分
- 执行指令总分

新字段会默认为0：
- 字画匹配朗读总分 = 0
- 字画匹配配画总分 = 0
- 执行指令朗读总分 = 0
- 执行指令配画总分 = 0

【数据迁移建议】
如果需要保留旧数据，可以：
1. 将旧的"字画匹配总分"平均分配到"朗读"和"配画"
2. 将旧的"执行指令总分"平均分配到"朗读"和"配画"
3. 或者重新评估这些维度

七、常见问题
------------

Q1: 为什么要拆分字画匹配和执行指令？
A: 为了更细致地评估不同能力，朗读和配画是两种不同的认知任务。

Q2: 维度名称必须完全一致吗？
A: 是的，switch语句是精确匹配的。建议使用带横杠的格式，如"字画匹配-朗读"。

Q3: 如果维度名称写错了会怎样？
A: 该维度的分数不会被保存，Console会没有对应的日志输出。

Q4: 可以只使用5个维度吗？
A: 可以，但不推荐。如果只配置5个栏目组，另外2个字段会保持为0。

Q5: 旧的存档数据会丢失吗？
A: 不会丢失，但旧数据中的"字画匹配总分"和"执行指令总分"字段不会自动迁移到新字段。
